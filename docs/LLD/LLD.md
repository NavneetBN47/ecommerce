# Low Level Design (LLD) Document\n## Shopping Cart Backend Service - Spring Boot MVC\n\n---\n\n## Executive Summary\n\nThis Low Level Design document provides comprehensive technical specifications for a Shopping Cart Backend Service built using Spring Boot MVC architecture. The service enables users to manage shopping carts with full CRUD operations on cart items, including adding products, updating quantities, and removing items. The system implements optimistic locking for concurrent cart modifications and follows RESTful API design principles.\n\n**Key Technologies:**\n- Spring Boot 3.x\n- Spring MVC\n- Spring Data JPA\n- PostgreSQL Database\n- Maven Build Tool\n- Java 17+\n\n**Core Capabilities:**\n- User cart management with lazy initialization\n- Product inventory tracking\n- Cart item CRUD operations\n- Optimistic locking for concurrent updates\n- RESTful API endpoints\n- Comprehensive validation and error handling\n\n---\n\n## 1. Functional Domain Breakdown\n\n### 1.1 User Management Domain\n**Responsibility:** Manage user accounts and authentication context\n\n**Components:**\n- User Entity\n- User Repository\n- User Service (if authentication is implemented)\n\n**Key Operations:**\n- User registration\n- User profile retrieval\n- User authentication context\n\n### 1.2 Product Catalog Domain\n**Responsibility:** Manage product inventory and availability\n\n**Components:**\n- Product Entity\n- Product Repository\n- Product Service\n\n**Key Operations:**\n- Product listing\n- Product details retrieval\n- Stock availability checking\n- Price management\n\n### 1.3 Shopping Cart Domain\n**Responsibility:** Core cart management functionality\n\n**Components:**\n- Cart Entity\n- CartItem Entity\n- Cart Repository\n- CartItem Repository\n- Cart Service\n- Cart Controller\n\n**Key Operations:**\n- Cart creation (lazy initialization)\n- Add item to cart\n- Update item quantity\n- Remove item from cart\n- Clear cart\n- Retrieve cart contents\n- Calculate cart totals\n\n---\n\n## 2. Entity Specifications\n\n### 2.1 User Entity\n\n**Table Name:** `USERS`\n\n**Attributes:**\n\n| Field Name | Data Type | Constraints | Description |\n|------------|-----------|-------------|-------------|\n| id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | Unique user identifier |\n| username | VARCHAR(50) | NOT NULL, UNIQUE | User login name |\n| email | VARCHAR(100) | NOT NULL, UNIQUE | User email address |\n| password | VARCHAR(255) | NOT NULL | Encrypted password |\n| first_name | VARCHAR(50) | NOT NULL | User first name |\n| last_name | VARCHAR(50) | NOT NULL | User last name |\n| created_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | Account creation timestamp |\n| updated_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | Last update timestamp |\n\n**Business Rules:**\n- Username must be unique across the system\n- Email must be valid format and unique\n- Password must be encrypted before storage\n- Soft delete not implemented (hard delete on account removal)\n\n### 2.2 Product Entity\n\n**Table Name:** `PRODUCTS`\n\n**Attributes:**\n\n| Field Name | Data Type | Constraints | Description |\n|------------|-----------|-------------|-------------|\n| id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | Unique product identifier |\n| name | VARCHAR(200) | NOT NULL | Product name |\n| description | TEXT | NULL | Detailed product description |\n| price | DECIMAL(10,2) | NOT NULL, CHECK (price >= 0) | Product unit price |\n| stock_quantity | INTEGER | NOT NULL, CHECK (stock_quantity >= 0) | Available inventory |\n| sku | VARCHAR(50) | NOT NULL, UNIQUE | Stock Keeping Unit |\n| version | INTEGER | NOT NULL, DEFAULT 0 | Optimistic locking version |\n| created_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | Product creation timestamp |\n| updated_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | Last update timestamp |\n\n**Business Rules:**\n- SKU must be unique across all products\n- Price must be non-negative\n- Stock quantity must be non-negative\n- Version field used for optimistic locking on concurrent updates\n- Products cannot be deleted if referenced in active carts\n\n### 2.3 Cart Entity\n\n**Table Name:** `CARTS`\n\n**Attributes:**\n\n| Field Name | Data Type | Constraints | Description |\n|------------|-----------|-------------|-------------|\n| id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | Unique cart identifier |\n| user_id | BIGINT | NOT NULL, FOREIGN KEY -> USERS(id), UNIQUE | Owner of the cart |\n| status | VARCHAR(20) | NOT NULL, DEFAULT 'ACTIVE' | Cart status (ACTIVE, CHECKED_OUT, ABANDONED) |\n| created_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | Cart creation timestamp |\n| updated_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | Last update timestamp |\n\n**Business Rules:**\n- Each user can have only one active cart (UNIQUE constraint on user_id)\n- Cart is lazily created on first item addition\n- Cart status transitions: ACTIVE -> CHECKED_OUT or ABANDONED\n- Cascade delete cart items when cart is deleted\n\n### 2.4 CartItem Entity\n\n**Table Name:** `CART_ITEMS`\n\n**Attributes:**\n\n| Field Name | Data Type | Constraints | Description |\n|------------|-----------|-------------|-------------|\n| id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | Unique cart item identifier |\n| cart_id | BIGINT | NOT NULL, FOREIGN KEY -> CARTS(id) | Reference to parent cart |\n| product_id | BIGINT | NOT NULL, FOREIGN KEY -> PRODUCTS(id) | Reference to product |\n| quantity | INTEGER | NOT NULL, CHECK (quantity > 0) | Number of units |\n| unit_price | DECIMAL(10,2) | NOT NULL | Price at time of addition |\n| created_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | Item addition timestamp |\n| updated_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | Last update timestamp |\n\n**Composite Unique Constraint:** (cart_id, product_id)\n\n**Business Rules:**\n- Each product can appear only once per cart (enforced by composite unique constraint)\n- Quantity must be positive (> 0)\n- Unit price captured at time of addition (price snapshot)\n- Cascade delete when parent cart is deleted\n- Quantity updates must check product stock availability\n\n---\n\n## 12. AND status = 'ACTIVE'\n    \n    alt Cart doesn't exist (Lazy Creation)\n        CartService->>CartRepository: save(new Cart)\n        CartRepository->>Database: INSERT INTO CARTS\n        Database-->>CartRepository: New cart created\n    end\n    \n    alt Optimistic Locking Failure\n        Database-->>CartService: OptimisticLockingFailureException\n        CartService->>CartService: Retry with exponential backoff\n        \n        alt All retries failed\n            CartService-->>CartController: throw OptimisticLockingFailureException\n            CartController-->>Client: 409 CONFLICT\n        end\n    else Success\n        Database-->>CartService: Cart item saved\n        CartService-->>CartController: CartItemDTO\n        CartController-->>Client: 201 CREATED\n    end\n```\n\n## 14. Database Model - PostgreSQL DDL\n\n```sql\n-- Create database\nCREATE DATABASE shopping_cart_db;\n\n-- Users table\nCREATE TABLE USERS (\n    id BIGSERIAL PRIMARY KEY,\n    username VARCHAR(50) NOT NULL UNIQUE,\n    email VARCHAR(100) NOT NULL UNIQUE,\n    password VARCHAR(255) NOT NULL,\n    first_name VARCHAR(50) NOT NULL,\n    last_name VARCHAR(50) NOT NULL,\n    created_at TIMESTAMP NOT NULL name VARCHAR(200) NOT NULL,\n    description TEXT,\n    price DECIMAL(10, 2) NOT NULL,\n    stock_quantity INTEGER NOT NULL,\n    sku VARCHAR(50) NOT NULL UNIQUE,\n    version INTEGER NOT NULL DEFAULT 0,\n    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,\n    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,\n    \n    CONSTRAINT products_price_non_negative CHECK (price >= 0),\n    CONSTRAINT products_stock_non_negative CHECK (stock_quantity >= 0)\n);\n\n-- Carts table\nCREATE TABLE CARTS (\n    id BIGSERIAL PRIMARY KEY,\n    user_id BIGINT NOT NULL UNIQUE,\n    status VARCHAR(20) NOT NULL DEFAULT 'ACTIVE',\n    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,\n    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,\n    \n    CONSTRAINT fk_carts_user_id FOREIGN KEY (user_id) REFERENCES USERS(id) ON DELETE CASCADE,\n    CONSTRAINT carts_status_valid CHECK (status IN ('ACTIVE', 'CHECKED_OUT', 'ABANDONED'))\n);\n\n-- Cart items
